# Mobile App Publishing Model

*Versión en español: [README.es.md](README.es.md).*

A neutral, reusable model of everything involved in publishing a mobile app to the App Store and Google Play: actors, platforms, credentials, artifacts, dependent steps, variation points, renewals and tracking milestones. It is instantiated per client without touching the model.

**Source of truth:** the JSON files in `model/`. Everything else is generated.

**Languages.** The repository (structure, keys, code, docs, skills) is in English. The model *content* — step names, notes, role descriptions, the generated page and diagram — is in Spanish, declared with `"lang": "es"` in each data file. See [docs/conventions.md](docs/conventions.md#language) for the rule and [docs/decisions.md](docs/decisions.md) for why.

## What is here

| Folder | What it is | Who edits it |
| --- | --- | --- |
| `model/` | The base model as JSON (10 files). | People or AI, with the `edit-model` skill. |
| `clients/<id>/instance.json` | What changes for one client: lanes, variants, dates, decisions. | Once per client, with the `instantiate-client` skill. |
| `generator/` | `build.py`, `validate.py`, `check_sources.py`, page templates, UI strings (`i18n/`). | Only to change how the page looks or works. |
| `dist/` | Generated: interactive page, SVG and PNG diagram, per-client diff. | Nobody. Regenerated by `build.py`. |
| `docs/` | How the model is built, conventions, decisions, data validation, deployment. | When the model changes. |
| `.claude/skills/` | Procedures for the AI: instantiate, edit the model, validate requirements. | When a procedure changes. |

## Usage

```bash
python3 generator/validate.py           # syntax, IDs and cross-references
python3 generator/build.py              # builds dist/ (PNG needs playwright)
python3 generator/build.py --no-png     # HTML, SVG and diff only
```

Open `dist/index.html` in a browser. Publishing it on GitHub Pages is optional; see [docs/deployment.md](docs/deployment.md#github-pages-optional).

## Two places, two uses

- **This repository** is the base model: versioned, shareable, with no real client data. The page it generates keeps tracking state only in the browser of whoever opens it.
- **The Claude artifact** (optional) is the day-to-day operations tool: same model, with tracking shared across the team and access roles. It is regenerated from here when the model changes. See [docs/deployment.md](docs/deployment.md).

Instances of real clients with internal information must not be pushed to a public repository. Keep this repository as the base and the instances in a private repository or in the artifact. See [Private client instances](docs/deployment.md#private-client-instances).

## Maintaining it with AI

Open the repository with Claude Code. `CLAUDE.md` tells it what to read for each task so it does not load the whole repository. The three usual procedures are skills:

- `/instantiate-client` — creates `clients/<id>/instance.json`, asking for lanes and variants.
- `/edit-model` — adds or changes a step, role, credential or variant while respecting IDs and dependencies.
- `/validate-requirements` — checks the data points with deadlines against Apple's and Google's official pages and updates `docs/validation.md`.

`.github/workflows/check-sources.yml` compares the cited official pages with a stored reference every month and opens an issue if any changed. `validate.yml` runs the validation and the build on every pull request to `main`.

## First steps in a new repository

```bash
git init && git add . && git commit -m "Mobile app publishing model"
python3 generator/check_sources.py --update   # initial reference of the official sources
git add generator/sources_hash.json && git commit -m "Add sources reference"
```

Optionally, publish on GitHub Pages and protect `main`: see [docs/deployment.md](docs/deployment.md#github-pages-optional) and [Branch protection](docs/deployment.md#branch-protection).
